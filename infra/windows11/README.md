# Развёртывание LztEvidence на Windows 11

Локальная установка изолирована от Razryad. Автоматическая доставка через Git push или CI не настроена.

Публичный адрес: https://nikolay.tailaf11dc.ts.net:8443/. Корень Windows: `C:\ProgramData\LztEvidence`; дистрибутив WSL: `LztEvidence`. Эти параметры описывают существующую установку; её текущее состояние требует проверки по месту.

Задача Windows `LztEvidence-Web` запускает CLI-супервизор при загрузке, поддерживает WSL и перезапускается после сбоя. Linux systemd управляет PostgreSQL 17, MinIO, `lzt-backend` и `lzt-web`. HTTP слушает `127.0.0.1:3000`, backend `127.0.0.1:8007`, приватное хранилище `127.0.0.1:9000`.

## Релизы и проверка

Исходники релизов находятся в `/opt/lzt/releases`; выбранный релиз задаёт `/opt/lzt/current`. Windows-файл `current.txt` сохраняет его идентичность. `release.json` фиксирует каждый файл исходников, ресурсов, каталога и детекторов. `package_release.py` упаковывает явный список файлов без секретов, пользовательских данных и прежних оценок качества. `setup_app.py` инициализирует только изолированные службы приложения. `activate_release.py` проверяет архив, сохраняет прежний выбор, проверяет чтение файлов допуска от имени пользователя сервиса до переключения и перезапускает только backend и веб-сервер приложения. Не редактируйте готовый релиз на месте.

Учётные данные владельца находятся в защищённом Windows-файле `C:\ProgramData\LztEvidence\secrets\admin-login.json`, логин `gorshenin-nik`. Ключ DeepSeek хранится в `secrets\deepseek_api_key`; перенос был согласован владельцем. Конфигурация Linux находится в `/etc/lzt` с режимом 0600. Не печатайте, не публикуйте и не коммитьте эти файлы.

`probe_credentials.py` сообщает баланс без вывода секретов. `probe_app.py` локально читает данные администратора и проверяет ресурсы, API, проекты, планы и обложки. Платный синтетический анализ включается отдельно через `--live-analysis` и `--series`; проверка не повторяет вызов модели. ID запусков и ключи идемпотентности сохраняются до опроса. После таймаута сначала прочитайте существующий запуск, затем решайте, нужны ли новые записи.

Логи Windows: `logs\supervisor.log` и JSON проверок в `logs`. Linux: `/var/log/lzt`, `journalctl -u lzt-backend -u lzt-minio -u lzt-web`. Постоянная БД: `/var/lib/postgresql/17/main`; объектное хранилище: `/var/lib/lzt/artifacts`. При исходной установке они были инициализированы заново, без копирования пользовательских данных.

## Бэкап и переключение

Запускайте `backup_app.py` от root через WSL. Скрипт временно останавливает только web/backend/MinIO приложения, создаёт PostgreSQL custom dump и архив хранилища/конфигурации в `C:\ProgramData\LztEvidence\backups\<UTC stamp>`, проверяет дамп через `pg_restore --list`, записывает манифест SHA-256 и запускает службы в `finally`. Бэкапы содержат секреты. Сохраните ограниченные Windows ACL и не добавляйте архивы в Git.

Keepalive проверяет службы каждые 30 секунд и может перезапустить их во время установки. Для согласованного бэкапа и переключения приостановите только точный процесс `/bin/sh /usr/local/sbin/lzt-keepalive`, закройте приём запросов через web и проверьте отсутствие queued/running задач и publishing submissions. При завершении, включая ошибку, возобновите keepalive и web.

После выбора релиза перезапустите backend. Проверьте, что `/proc/<MainPID>/cwd` указывает на backend выбранного релиза, и прочитайте компактный API через публичный HTTPS. Готовность API и правильная символьная ссылка сами по себе не доказывают, что процесс импортировал нужные исходники.

Восстановление заменяет данные и требует отдельного решения. Сначала сделайте новый бэкап, остановите только web/backend/MinIO приложения, проверьте все хеши выбранного бэкапа. Восстановите custom dump в БД этого приложения через `pg_restore --clean --if-exists --no-owner --no-acl` с его приватными локальными данными доступа. Восстановите `artifacts` и `config` из парного архива. Верните владельца хранилища `lzt:lzt`, владельца конфигурации root и режим секретов 0600. Выберите соответствующий релиз из `release.json` бэкапа, запустите службы и проверьте готовность, исходные изображения, планы и публичный HTTPS. Не затрагивайте другие приложения и не сбрасывайте Funnel. Это описанная процедура; разрушительное восстановление в приведённых проверках не выполнялось.

### Права файлов допуска фото, 2026-10-20

Сохранённый frontend-релиз `38270177998b4504` содержит `backend/admission/exclusions/held_out_evaluation.json` с root:root 0600. Запуск валидатора от lzt воспроизводил PermissionError для одиночного и серийного ввода до регистрации отправки. Общая граница API преобразовывала исключение в HTTP 503. В установленном на момент проверки преемнике доступ был исправлен; публичные запросы одиночного фото и серии завершились успешно.

Общий `unpack_release` нормализует каталоги допуска до root:lzt 0750 и JSON до root:lzt 0640, затем разбирает манифест и исключения от lzt до изменения `current` или `current.txt`. Неуспешная проверка сохраняет прежний выбор. Защита применяется при первоначальной установке и активации. Приватные логи допуска различают этапы валидации, регистрации и публикации, классы исключений и места в коде без тел запросов и секретов.

Дополнительная серия реальных фотографий выявила ложное отклонение фразы «План не привязан: выводы о рисках плана, задержках и графике не делаются». Старый валидатор трактовал оговорку как утверждение о задержке. Исправленная проверка принимает полное отрицательное перечисление конкретных предметов плана; смешанные утвердительные фразы отклоняются. Прошли 24 целевых случая задержек/безопасности. Сохранённый ответ провайдера прошёл полную гибридную валидацию в памяти без нового вызова. Исходный неуспешный запуск и платные квитанции сохранены.

### Компактный статус и помощник, 2026-10-20

Интерфейс запрашивает `GET /runs/{id}` с `X-Response-Detail: summary`. Ответ сохраняет состояние, выводы, ссылки на источники и основания наблюдений, но опускает повторные исходные запросы/ответы провайдера в `ai_evidence.result`. Обычный ответ API и неизменяемые сохранённые основания не меняются. Для неуспешного запуска из трёх фото измерено 15,222,566 байт полного ответа и 67,119 байт компактного. Чтение статуса ограничивает чтение JSON и повторяется после временных ошибок без объявления работающего анализа неуспешным.

Помощник читает состояния фото и видео, приоритетно включает активные задачи в ограниченный контекст и отличает отсутствие времени от нулевого времени. Контекст и встроенная справка содержат известные описания ошибок. Старые ответы отображаются с общим названием модели без переписывания сохранённых диалогов. Эти результаты относятся к проверенной тогда версии и не заменяют проверку очередного релиза.
