Жюри и заказчику три тематические страницы объясняют результат и его ограничения. Разработчику схемы и ссылки на исходники помогают найти обработку фотографий, правила сравнения и места хранения данных.

Документация описывает текущий код и конфигурацию репозитория. Она не подтверждает точность распознавания или состояние удалённого сервера. Условия независимой проверки качества приведены в [инструкции оценки](../evaluation/hybrid/README.md).

После неудачного фотоанализа редактор может восстановить упавший этап в том же анализе. URL и запись истории сохраняются. Успешные облачные ответы и результаты детекторов используются повторно. Сначала сервер полностью перепроверяет сохранённый отклонённый ответ исходной моделью и валидатором, без обращения к провайдеру. Успешная перепроверка создаёт отдельную квитанцию с `source_call_id`, `validation_revision` и `usage=null`; исходный ответ остаётся неизменным. Если полная проверка не прошла, явная попытка может сделать новый платный вызов только для неуспешного элемента. Неизвестный исход вызова не считается успехом. Автоматических платных повторов нет.

API: `POST /runs/{run_id}/stages/{stage}/retry`, заголовок `Idempotency-Key: <UUID>`, без тела. Ответ202: `{"run_id":"...","attempt_id":"..."}`. Только owner/editor и только действительно упавший этап; проверяются действующий исходный профиль, согласие и целостность источников. Повтор того же ключа возвращает ту же попытку, включая потерянный ответ. Клиент сохраняет ключ до определённого исхода и ожидает fetch вместе с JSON до180 секунд; загрузка страницы и polling не отправляют POST. `GET /runs/{id}` возвращает `current_attempt_id`, историю `attempts` и `stages[].retryable/retry_cost`. `retry_cost=true` означает, что может понадобиться новый облачный вызов. Конфигурация анализа, исходные файлы, привязка плана и уже зарезервированный контекст оценки (включая историю) не меняются. Все прежние квитанции видны в `ai_evidence`; `effective` отмечает используемые текущей попыткой.

Сбой ответа `status=incomplete, incomplete_details.reason=max_output_tokens` диагностируется как `response_output_truncated`; частичный JSON не принимается. Установленные профили и их точные промпты/хэши сохранены. В новых запросах ограничивается только длина описательных строк в допустимом подмножестве схемы, без сокращения списков объектов и ссылок на доказательства. Лимит токенов не увеличен.

Совместимый старый API `POST /runs/{run_id}/retry` сохраняет прежнее поведение: необязательное тело `{"repeat_processing": true}` (до1024 байт) явно разрешает полную новую обработку со связанным анализом. Пустое тело или `false` разрешают её лишь до первого облачного вызова. Новый интерфейс использует восстановление этапа.
