# Проверка CI

Workflow `.github/workflows/verify.yml` проверяет frontend (тесты и production build), backend-контракты, миграции и реальное взаимодействие с PostgreSQL 17.6 и MinIO. Моки наблюдателя в контрактных тестах не являются доказательством качества модели.

Для запуска нужны GitHub Actions secrets `EVALUATION_ARCHIVE_URL` и `CATALOG_WORKBOOK_URL`, а также `ANNOTATION_ARCHIVE_URL` для исходных PNG организаторов: доступные runner ссылки на разрешённый архив и исходный XLSX. Отсутствие этих источников намеренно завершает job ошибкой. Архив проверяется тестами по фиксированному хешу; данные не коммитятся.

Linux job явно исключает только `test_offline_cpu_admission_publishes_and_authorizes`: профиль наблюдателя ограничен macOS ARM64. Этот тест запускается отдельно на согласованном Apple M3 Pro с тем же commit и pinned snapshot, настоящими PostgreSQL/S3. Локальная проверка записывается в release evidence отдельно от CI. Не следует считать успешный Linux job доказательством допуска модели, независимой приёмки или установки сервиса.

Workflow не содержит deploy job. Релиз требует отдельной независимой разметки, результатов оценки и подтверждения установленного сервиса. Платные API-вызовы закрыты кодом `cloud_budget_reservation_unavailable` до внедрения проверяемого верхнего резерва стоимости в общем бюджете 1000 RUB.

Разметчик отдельно проходит checksum-сборку и headless Chromium-проверку рисования, подтверждения, сохранения, импорта/экспорта, защиты от повреждённых данных и масштаба на мобильном экране. Скриншоты содержат тестовую разметку и не являются эталоном или результатом модели.
