## Findings

### F1 — Runtime reconciliation can interrupt a live submission

**Instance: fix now. Prevention:** re-check earlier rejected race findings when a caller changes from startup-only to runtime. `backend/app/application/executor.py:171–175,181–182` calls reconciliation after recovery while submission remains enabled. `backend/app/adapters/postgres.py:86–96,129–132` protects leased runs but quarantines pre-run intents and fails every publishing submission without publisher ownership. Story 1.3's rejection relied on startup-only reconciliation (`spec-1-3-complete-a-single-image-observation-run.md:81`); Story 1.8 invalidated that premise. Independently reported by adversarial and edge-case lenses; primary code re-read.

### F2 — SPA document routes collide with the API proxy

**Instance: fix now. Prevention:** exercise the documented server topology with an HTML navigation request. `web/vite.config.ts:6` proxies every `/runs` request; `web/src/App.tsx:384` uses that same namespace for history navigation, while `backend/app/main.py:159–167` returns JSON. `web/README.md:13` prescribes both proxying and history fallback for the same path. Direct navigation/reload therefore does not serve the Run Workspace. Adversarial lens; primary configuration re-read.

### F3 — Terminal publication errors keep the form permanently pending

**Instance: fix now. Prevention:** test API error codes jointly with client retry state. `backend/app/main.py:148–153` returns 503 for terminal `submission_publication_failed`/`submission_interrupted`; `backend/app/adapters/postgres.py:470–483` retains the failure under that key. `web/src/App.tsx:520–541` clears only 4xx or accepted run responses, treats that terminal 503 as uncertainty, and keeps the same key. Pending state disables editing (`:588–591`) and survives reload. An explicit fresh submission is needed after an authoritative terminal failure, while genuinely uncertain sends must retain their key. Edge-case lens; primary paths re-read.

### F4 — Applied usability thresholds are outside the immutable policy

**Instance: fix now. Prevention:** reconcile policy decisions against the architecture before introducing a numeric gate. `backend/app/application/executor.py:70–75,134–141` suppresses inference for dimensions below 64 or per-channel ranges below 5. `backend/app/adapters/postgres.py:525` snapshots only policy intent/revision. Architecture spine AD-8 (`:75`) assigns usability to PolicyProfile; its Deferred Decisions (`:291`) requires an evidence-backed revision for resolution/visibility gates. Remove the unsupported heuristic or propose an explicitly approved, evidenced immutable policy; do not silently rewrite the canonical spec. Adversarial lens; primary code and architecture re-read.

### F5 — Series stage completion precedes the work it represents

**Instance: fix now. Prevention:** assert stage truth during the second/later frame, not only at terminal success. The per-frame loop (`backend/app/application/executor.py:133–138`) reads/checks each frame just before observing it, while the first reservation succeeds the run-level usability stage (`backend/app/adapters/postgres.py:599–600`). Later frames remain unchecked when the API reports that stage succeeded. Epic acceptance requires factual persisted progress (`epics.md:574–577`). Define and implement truthful aggregate stage transitions. Adversarial lens; primary paths re-read.

### F6 — Rendered UI acceptance has no verification evidence

**Instance: fix now, verification outstanding. Prevention:** distinguish component verification from rendered acceptance in completion records. `web/vite.config.ts:7` uses jsdom; `web/src/App.test.tsx:34–46` substitutes object URLs, dialog methods, and non-JPEG blob content. It cannot establish 320px/200% zoom layout, native dialog focus, or actual source-image rendering. These are declared criteria (`epics.md:556–559,569–572,602–605`), explicitly unverified in Stories 1.5–1.7. No GUI was used in this retrospective, in accordance with the user boundary. This is missing evidence, not an observed visual defect. Verification-gap lens; configuration/tests and story records re-read.

### F7 — IndexedDB recovery branch lacks a regression assertion

**Instance: defer, tracked. Prevention:** test each durable storage branch with a realistic failure trigger. `web/src/App.tsx:136–190` falls back to IndexedDB after sessionStorage failure. `web/src/App.test.tsx:229–254` verifies tiny sessionStorage payloads only. Force quota exhaustion, persist/recover the exact body/key through IndexedDB, and verify definitive-response cleanup. Story 1.5 already records this limitation (`:124`). Verification-gap lens; primary test branch re-read.

### F8 — Batch timeout is recorded but not enforced

**Instance: defer, tracked contract gap. Prevention:** trace each snapshotted runtime limit to its enforcement site. `backend/app/adapters/postgres.py:393–404` records the batch bound; `backend/app/application/executor.py:129–162` reads only the per-image limit. Architecture AD-30 (`:171`) declares both. No over-budget batch was measured in this retrospective; do not claim a demonstrated timeout breach. Apply one monotonic deadline across the series and test the remaining budget.

### F9 — An unresolved submit fetch has no client deadline

**Instance: defer, tracked. Prevention:** include a transport that neither resolves nor rejects. `web/src/App.tsx:511–519,543–545` releases `sending` only when fetch settles; no abort deadline exists. Preserve the durable exact request/key on timeout and make retry available. This is a static edge-case finding; no real stalled network was induced.
