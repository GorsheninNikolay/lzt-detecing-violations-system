# Историческая очередь разметки восьми классов

Подготовка через DINO выведена из исполнения. Текущий путь описан в [README](../../README.md). Результаты ниже относятся к сохранённому черновику и не подтверждают качество текущей версии.

`draft-annotations.json` охватывает все 100 PNG организатора. Он сохраняет хеши архива и изображений, размеры, закреплённую версию Grounding DINO Tiny, хеш адаптера и непроверенных кандидатов техники. Это не метки, обучающие цели или результаты оценки. Архив не подтверждает площадку, камеру, время съёмки или группы серий. Очередь намеренно не разделена на обучение, валидацию и независимую оценку.

Историческое воспроизведение с проверенным снимком модели:

```sh
PYTHONPATH=backend uv run --project backend --extra test python scripts/prepare_expansion_annotations.py \
  --snapshot-dir /private/tmp/grounding-dino-tiny-e08274d
```

`scripts/prepare_expansion_annotations.py` относится к локальным инструментам и больше не поставляется с репозиторием. Команда сохранена как описание происхождения артефакта, для её выполнения нужна отдельная локальная копия.

## Порядок проверки разметки

1. Подтвердите права и происхождение изображений. Запишите реальные площадку, камеру и серию. Неизвестные группы пригодны для демонстрации или предварительного разбора, но их нельзя разделять как независимые площадки.
2. Исправьте или удалите каждого кандидата техники. Добавьте пропущенные объекты, включая несколько объектов одного класса. Различайте грузовик и самосвал, автокран и кран-манипулятор. Если ракурс не позволяет определить класс, запишите `uncertain` или `unassessable`.
3. Проверьте пять признаков сцены отдельно от техники. Рамки, где они осмысленны, и наличие или отсутствие признаков требуют отдельных решений человека. Готовая конструкция сама по себе не доказывает выполнение работ.
4. Проверьте допустимые гипотезы этапа для кадров и серий, включая неоднозначность. Для каждого сценария нужны положительные, отрицательные, неоднозначные и непригодные серии с конкретным планом участка и ожидаемым состоянием сигнала.
5. Сохраните проверенные метки в отдельном файле с указанием проверяющего. Не перезаписывайте `draft-annotations.json` и не используйте `equipment_candidates`, `scene_candidates` или `stage_candidates` как эталон.
6. Разделите набор по подтверждённым группам площадка/камера/серия. Сохраните существующий независимый двухклассовый набор. Оцените precision/recall по классам, локализацию рамок, согласие по этапам, частоту ложных сигналов и задержку CPU. Затем проводите новый допуск профиля.

В сохранённом черновике модель выдала 97 кандидатов техники на 100 изображениях: 42 бетономешалки, 38 экскаваторов, 15 бульдозеров и 2 дорожных катка. Для остальных четырёх классов кандидатов нет. Это распределение ответов модели, не состав архива. При визуальной проверке `Screenshot_87.png` обнаружено вероятное смешение классов; черновик не подтверждает готовность.

Связанный с организатором [набор GitHub](https://github.com/miniexcav/Construction-Machines-Images-Dataset) содержит 223 изображения экскаваторов с YOLO-разметкой. Авторы описывают сбор изображений из сети, учебное/исследовательское использование и возможные права третьих лиц. Сам по себе набор не закрывает требования восьми классов, коммерческих прав и независимых площадок.
