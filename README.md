# Контроль строительства

## О проекте

Приложение помогает заказчику и специалисту строительного контроля разбирать фотографии площадки. Оно находит видимую технику, описывает признаки сцены и сопоставляет наблюдения с планом выбранного участка. Пользователь получает фотографии с разметкой, предположения об этапах работ и сигналы с основаниями для проверки на месте.

Можно загрузить один снимок или серию из 2–8 фотографий JPEG/PNG. Для серии указываются порядок и время съёмки. Оригиналы сохраняются: к ним можно вернуться при разборе результата. В карточке анализа доступны объяснения и ограничения выводов, а исправления разметки и подтверждение этапа хранятся отдельно от ответа модели.

Проект служит прототипом поддержки решений. Результаты требуют проверки человеком: снимок не подтверждает отсутствие техники на всей площадке, нарушение норм или отставание от графика.

## Как работает

Основной режим использует гибридный анализ:

1. Сервер сохраняет фотографии и учитывает их ориентацию.
2. Две YOLO на процессоре сервера предлагают классы техники и рамки объектов.
3. Мультимодальная модель сверяет предложения с каждым снимком, затем разбирает серию целиком с контекстом участка.
4. Приложение сопоставляет наблюдения со сроками и техникой в сохранённой версии плана, если она выбрана.
5. Человек просматривает основания сигналов, исправляет разметку и принимает решение об этапе и дальнейшей проверке.

Неопределённость остаётся частью результата. Объект можно сохранить со свободным названием, неизвестным классом или без рамки. Отдельно поддерживается анализ только через Мультимодальную модель, без YOLO; его настройка описана в инструкции запуска.

## Быстрый старт

Для основного пути нужны Node.js/npm, `make`, `curl` и работающий Docker Compose. Makefile также поддерживает другой совместимый Compose-провайдер. Python и uv на хосте не требуются: backend собирается внутри контейнера.

До запуска положите исходный XLSX-каталог в `artifacts/dataset/Свод*.xlsx`, а два файла весов гибридного режима в `artifacts/Models/apoce.pt` и `artifacts/Models/kaggle.pt`. Эти артефакты нужно получить отдельно. Пустая таблица или произвольные веса не заменяют исходные файлы.

Из корня репозитория выполните:

```sh
make up
```

Команда собирает интерфейс и контейнеры, запускает приложение, базу и файловое хранилище, затем проверяет готовность API. Адрес приложения: <http://127.0.0.1:8096>. Данные сохраняются в постоянных томах; `make down` останавливает контейнеры, сохраняя эти тома.

Для запуска анализа требуется [настроенный облачный профиль](infra/deploy/README.md#cloud-profile). Без него можно открыть интерфейс и читать сохранённые данные. Перед публичным размещением настройте внешний контроль доступа: пользовательские функции API доступны без входа в аккаунт.

## Первый анализ

Создайте или выберите проект и участок. Добавьте фотографии одного участка, проверьте порядок и время съёмки каждого кадра. При необходимости сохраните план с работами, сроками и ожидаемой техникой. Если план уже есть, сопоставление включается по умолчанию; его можно отключить перед запуском.

Дайте согласие на передачу выбранных фотографий и контекста в облако. Без согласия анализ не запускается. После обработки просмотрите снимки, найденные объекты, объяснение этапа и основания каждого сигнала. Проверьте сомнительные находки и при необходимости исправьте разметку или подтвердите этап.

Без плана доступны наблюдения и разбор видимой сцены; данных для вывода об отставании нет. Недостаток пригодных снимков также отражается в результате. Добавление плана или его изменение позже не меняет уже сохранённый анализ.
