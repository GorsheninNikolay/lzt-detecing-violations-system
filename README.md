# Контроль строительства

Сервис помогает разбирать фотографии строительной площадки: сохраняет исходные кадры, распознаёт видимую технику и признаки сцены через мультимодальную модель в Yandex AI Studio, затем один раз сопоставляет наблюдения с контекстом участка и привязанной ревизией плана. Результат содержит гипотезу этапа, риски для проверки, рекомендации и ограничения. Подтверждение человеком хранится отдельно. Это прототип поддержки решений, не автоматическая фиксация нормативных нарушений.

Гибридный путь: фотографии → обе модели YOLO на CPU сервера → согласование объектов мультимодальной моделью → один анализ фотографий и зафиксированного контекста → сохранённые сигналы. Старый профиль только с мультимодальной моделью остаётся совместимым. Используется `deepseek-v4.1-flash/latest`, reasoning `none`, temperature `0`, max output `8192`, `store=false`, журналирование данных провайдером отключено. Версия `latest` у провайдера не гарантирует неизменность весов: фактический URI модели, сведения об использовании и полный ответ сохраняются.

## Быстрый запуск локально

Нужны Python 3.13.15, uv, Node.js/npm, Docker Compose либо Podman с Compose. Приложение использует PostgreSQL и приватный S3; SQLite и публичный бакет не поддерживаются. Данные, изображения и история сохраняются в томах. Не удаляйте тома при обновлении.

Из корня репозитория:

```sh
make up
```

Makefile устанавливает npm-зависимости, собирает frontend и контейнеры, запускает
PostgreSQL, MinIO и приложение, затем проверяет готовность API. Адрес:
`http://127.0.0.1:8096`. Для этого пути Python и uv на хосте не нужны: backend
собирается внутри контейнера. Нужны Node.js/npm и работающий Docker Compose
либо Podman с установленным Compose-провайдером (`podman machine start` на macOS).
Docker выбирается автоматически, если установлен; иначе используется Podman.

`make down` останавливает контейнеры, сохраняя тома; `make logs`, `make status`
и `make check` показывают логи, состояние и готовность. Другой порт:
`make up PORT=8097`; явный движок: `make up COMPOSE="podman compose"`.
Для следующих команд используйте те же переопределения. Локальный Compose-проект
называется `construction-evidence-local`; пароли по умолчанию предназначены
для локального запуска и могут быть заменены через окружение.
Выберите пароль PostgreSQL до первого запуска и используйте его далее:
смена переменной не меняет пароль роли в уже созданной БД. Для другой
конфигурации можно выбрать отдельный `COMPOSE_PROJECT`, сохранив старые тома.

Для анализа передайте облачные переменные, описанные ниже, выполните
`make profile`, задайте выданный UUID как `OBSERVER_PROFILE_ID` в окружении
и повторите `make up`. Без профиля доступны интерфейс и чтение данных.

Ручной запуск (без Makefile):

```sh
uv sync --project backend --extra test
npm --prefix web ci
npm --prefix web run build
```

Перед сборкой нужен исходный XLSX каталога в `artifacts/dataset/Свод*.xlsx`; это отдельный входной артефакт. При его отсутствии запросите исходный каталог, не создавайте пустую замену. `init` применяет миграции с сохранением существующих данных и импортирует каталог, сохраняя исходные коды и номера строк. Каталог работ сам по себе не задаёт календарный план.

Задайте в окружении `POSTGRES_PASSWORD`, `MINIO_ROOT_PASSWORD`, `DEPLOY_PORT=8096`. Пароли должны быть разными и URL-safe для строки подключения. Ключ облака вводите интерактивно, не сохраняйте в репозиторий и не печатайте. Для начального запуска без исполнения анализов ключ и профиль не нужны.

```sh
docker compose -f infra/deploy/compose.yaml build
docker compose -f infra/deploy/compose.yaml up -d
curl --fail http://127.0.0.1:8096/api/health/ready
```

Проверка готовности подтверждает доступность БД, миграций, приватного S3, восстановление прерванных публикаций и, если задан профиль, конфигурацию исполнителя. Она не делает платный запрос модели и не доказывает качество распознавания. Без `OBSERVER_PROFILE_ID` чтение работает, запуск анализа отвечает `profile_unauthorized`.

Для настоящих анализов задайте `YANDEX_CLOUD_FOLDER_ID` и `YANDEX_AI_STUDIO_API_KEY` в окружении. У ключа должно быть право исполнения foundation models. Создание профиля не вызывает модель:

```sh
docker compose -f infra/deploy/compose.yaml run --rm backend evidence-profile
```

Команда печатает только UUID профиля. Сохраните его как `OBSERVER_PROFILE_ID` и пересоздайте backend с новым окружением. Профиль содержит настройки и версии инструкции/схемы, но не секрет. Сервис выдаёт доступ к изображениям и анализам без авторизации, а запуск может расходовать облачную квоту: перед публичным размещением настройте нужный внешний контроль доступа. В этой реализации удалённое развёртывание не выполнялось.

## Первая проверка

Создайте проект и участок, при необходимости сохраните план. Загрузите JPEG/PNG, проверьте порядок и время съёмки. Отдельно отметьте согласие на передачу именно этих фотографий и контекста в облако. Без `cloud_processing_consent: true` запрос отклоняется. EXIF-ориентация учитывается; рамки относятся к ориентированному изображению. Исходный файл сохраняется без изменений.

[ReDoc](http://127.0.0.1:8096/api/redoc), [Swagger](http://127.0.0.1:8096/api/docs), [OpenAPI JSON](http://127.0.0.1:8096/api/openapi.json). При прямом запуске backend доступны `/redoc`, `/docs`, `/openapi.json`. Примеры запросов и описание ошибок: [docs/API_EXAMPLES.md](docs/API_EXAMPLES.md).

Без плана система сообщает, что данных для вывода об отставании недостаточно. Необнаружение объекта не доказывает его отсутствия. Риски безопасности ссылаются на видимые наблюдения конкретных кадров; расстояния, соответствие нормам и нарушения не считаются подтверждёнными. Свободные названия техники, неизвестный класс, отсутствие рамки и отсутствие числовой уверенности сохраняются как есть. Каталог из восьми классов автоматически не расширяется.

## Надёжность и история

`Idempotency-Key` связывает загрузку с её исходным телом. При потере HTTP-ответа повторите тот же ключ и тело. Другие данные с тем же ключом дают `409`. Это не повтор запроса к модели. Каждый облачный вызов резервируется в PostgreSQL до отправки. После неопределённого исхода он не повторяется автоматически, а повтор запуска с уже зарезервированным вызовом запрещён. Ручной повтор допустим лишь для сбоя до первого обращения к провайдеру; новый анализ требует отдельного осознанного действия.

Наблюдения кадров, порядок, времена, ревизия плана и до трёх более ранних успешных анализов того же участка фиксируются перед единственным аналитическим вызовом. Без участка или надёжных времён история не используется. Позднейшие и чужие участки исключаются. Исходный ответ, нормализованный результат, сведения об использовании и версии инструкции/схемы неизменяемы.

DINO/Qwen выведены из исполнения: новые запуски, допуск и повторы запрещены. Старые профили, изображения, исправления, сравнения и отчёты сохранены. У старых запусков `ai_assessment` равен `null`. Архив экспериментов доступен отдельно от основного сценария демонстрации. Исправление разметки создаёт новую версию, не переписывает ответ модели. Экспорт в YOLO/COCO требует явного сопоставления с восьмиклассовым каталогом, проверки всего кадра и одобрения владельцем; изображения независимого контрольного набора и другие зарезервированные изображения исключаются независимо от согласия пользователя.

## Окружение и эксплуатация

| Переменная | Назначение |
| --- | --- |
| `API_ROOT_PATH` | Префикс OpenAPI: `/api` в Compose, пусто при прямом запуске; относительные URL документации работают в обоих случаях |
| `DATABASE_URL` | `postgresql+psycopg://…`; для прямого backend |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Приватный S3, без анонимного чтения |
| `S3_REGION` | По умолчанию `us-east-1` |
| `YANDEX_CLOUD_FOLDER_ID` | Каталог Yandex для создания профиля |
| `YANDEX_AI_STUDIO_API_KEY` | Только временное окружение, без записи в логи |
| `OBSERVER_PROFILE_ID` | UUID текущего профиля мультимодальной модели или hybrid-профиля |
| `HYBRID_PHOTO_SIGNALS` | `1` при создании нового hybrid-профиля; Compose по умолчанию `1` |
| `YOLO_MODELS_DIR` | Каталог оригинальных `apoce.pt` и `kaggle.pt`; Compose монтирует только для чтения |
| `POSTGRES_PASSWORD`, `MINIO_ROOT_PASSWORD`, `DEPLOY_PORT` | Compose |

Прямой запуск: `cd backend`, `uv run alembic upgrade head`, затем `uv run evidence-service`. Для каталога используется `app.application.site.ensure_catalog`; Compose вызывает его автоматически. Миграции инициализации не изменяют исторические результаты. После обновления версии инструкции/схемы создайте новый профиль.

Для отдельного локального порта backend: `uv run uvicorn app.main:app --host 127.0.0.1 --port 58049`. Из корня запустите web командой `API_PROXY_TARGET=http://127.0.0.1:58049 npm --prefix web run dev -- --port 58149`; документация будет доступна на `http://127.0.0.1:58149/api/redoc`. При таком dev-прокси оставьте `API_ROOT_PATH=/api`, а без префиксного прокси задайте пустую строку. Источник облачных ключей должен оставаться в окружении, не в командах и файлах проекта.

```sh
docker compose -f infra/deploy/compose.yaml logs --tail=100 backend init
curl --fail http://127.0.0.1:8096/api/health/live
curl --fail http://127.0.0.1:8096/api/health/ready
```

`database_migration_mismatch` требует миграции; `artifact_gate_failed` требует проверки приватного S3 и доступов; `profile_unauthorized`/`profile_runtime_mismatch` требуют проверки UUID/версии профиля. `cloud_consent_required`, `profile_retired`, `provider_call_not_replayable` требуют исправления действия, а не автоматического повторения. `observer_timeout`, ошибки транспорта и неполный ответ оставляют сохранённую резервацию. Просматривайте `GET /runs/{id}`; не удаляйте записи резервации ради повторного вызова.

Кабинет владельца: `/admin`. Установка пароля из терминала: `cd backend && uv run python -m app.application.admin_password` (ввод скрыт). Логин `gorshenin-nik`; пароль минимум 8 символов. Кроме loopback требуется HTTPS, а изменения требуют точный `Origin` и `X-CSRF-Token`. Сессия HttpOnly, срок 8 часов. Смена пароля завершает сессии.

Loopback-исключение действует при прямом обращении к backend и локальном dev-прокси. Контейнерный nginx обращается из отдельной сети, поэтому административный вход через стандартный HTTP Compose требует настройки TLS и доверенного прокси; [подробности](infra/deploy/README.md).

## Разработка и проверка

[Architecture.md](Architecture.md) описывает текущий и будущий пути; [docs/CODE_GUIDE.md](docs/CODE_GUIDE.md) описывает модули и сущности. Windows-набор для двух независимых YOLO-профилей: [training/windows/README.md](training/windows/README.md). Оригинальные веса `artifacts/Models/{apoce,kaggle}.pt` подключаются только для чтения. Их SHA-256, исходные классы и отображение фиксирует `backend/app/data/yolo-manifest.json`. Качество не подтверждается техническим запуском; [инструкция гибридного анализа](docs/HYBRID_PHOTO_SIGNALS.md).

```sh
uv run --project backend --extra test pytest backend/tests/test_deepseek.py -q
npm --prefix web test -- --run
npm --prefix web run build
```

Для DB/S3 проверок задайте отдельные `TEST_DATABASE_URL` и `TEST_S3_BUCKET`, отличающиеся от рабочих. Полный набор: `uv run --project backend --extra test pytest backend/tests -q`. Тесты нового адаптера используют только симулированные ответы; пробный технический запуск не подтверждает точность модели или качество оценки безопасности. [Фактические результаты проверки](docs/DEEPSEEK_VERIFICATION.md) содержат успешную проверку всех 257 backend-сценариев и историю очистки устаревшего набора.
